### How Developer Work Has Changed
- Broad shift across all panelists: from writing and reviewing code by hand to operating at the level of ideas and decisions
- Models have improved dramatically; code now tests and merges itself
- One panelist noted: “I am not involved in writing or shipping the code anymore, which is kind of a problem, but also kind of wild”
- Open source work flagged as a specific concern: preserving the human element and collaborative fun amid well-intentioned but overwhelming AI contributions

### Enhanced Notes

#### Enterprise Conversation: Redesign Roles Without Losing Accountability
- Frame agent adoption as a change in work allocation, not simply a headcount or code-volume opportunity. Identify which decisions still require domain expertise, system ownership, and accountable approval.
- Define review responsibilities for human-authored and agent-authored changes, including how teams handle high-risk changes, ambiguous requirements, and generated contributions to shared or open-source projects.
- Preserve collaboration by making proposals, rationale, tests, and provenance visible to teammates; avoid measuring success only by number of agents or generated changes.
- Provide role-based training for writing clear tasks, evaluating agent output, escalating uncertainty, and declining unsafe recommendations. Give teams a channel to report workflow friction and unintended effects.
- Establish adoption measures that include delivery outcomes, defect rates, review quality, developer experience, and open-source maintainer burden.
